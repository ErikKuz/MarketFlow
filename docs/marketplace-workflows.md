# Рабочие процессы MarketFlow

Этот этап добавляет историю заказов, обработку частей заказа продавцами, срок оплаты,
ожидающие начисления, вывод условных средств, возврат после получения, модерацию,
поиск по каталогу и кабинеты владельца и аналитика.

## Правила

- При создании заказа остатки резервируются, ставка комиссии сохраняется в заказе.
  Срок оплаты по умолчанию — 30 минут. Изменение комиссии влияет только на новые заказы.
- Для каждого продавца создаётся `SellerOrderEntity`. Его цепочка:
  `NEW → ACCEPTED → PACKING → SHIPPED → DELIVERED`.
  Продавец управляет только своей частью; получение подтверждает покупатель.
- После получения всех частей общий заказ становится `COMPLETED`.
  Срок подачи заявки на полный возврат по умолчанию — 7 дней.
- При оплате начисления продавцам и комиссия попадают в `pendingBalance`.
  После завершения срока возврата фоновая задача переводит их в доступный `balance`.
  Открытая заявка на возврат приостанавливает этот перевод.
- Одобрение возврата возвращает деньги на исходную карту покупателя, отменяет начисления
  и при указанном решении возвращает товары на склад. История доставки сохраняется:
  заказ остаётся `COMPLETED`, а оплата становится `REFUNDED`.
- Вывод резервирует доступные средства в `withdrawalReserved`. Владелец подтверждает
  зачисление на выбранную собственную карту продавца либо отклоняет заявку.
  Это учебные балансы, без интеграции с банковским платёжным провайдером.
- Регистрация с `accountType=SELLER` создаёт покупателя и заявку `PENDING`.
  Роль продавца и кошелёк появляются после одобрения. Роли и статус пользователя
  перечитываются для действующей сессии при следующем запросе.
- Ключевые переходы, решения и финансовые действия записываются в `audit_events`.

Ограничения этапа: возврат оформляется на весь полученный заказ, частичного возврата
нет; отмена покупателем разрешена до начала обработки продавцом. RabbitMQ и Redis
на этом этапе не подключаются. Для новых REST-маршрутов отдельная OpenAPI-спецификация
пока не добавлена; существующие YAML описывают прежние API.

## Где открыть

- `/workspace` — вход в кабинеты по ролям.
- `/account/orders` — заказы покупателя.
- `/workspace/seller/orders` — части заказов продавца.
- `/workspace/finance` — история операций, кошелёк и заявки на вывод.
- `/workspace/seller-application` — заявка продавца.
- `/workspace/moderation` — заявки и видимость товаров.
- `/workspace/owner` — комиссия, сотрудники, выплаты, возвраты и аудит.
- `/workspace/analytics` — отчёт за период.
- `/catalog` — поиск, фильтры, сортировка и страницы каталога.

REST-аналоги находятся в `RestMarketplaceController` под `/api/v1`.
Изменяющие запросы требуют сессию, нужную роль и CSRF-токен.

## Настройки запуска

Первоначальный владелец создаётся из переменных окружения `MARKETFLOW_OWNER_EMAIL`
и `MARKETFLOW_OWNER_PASSWORD` (не менее 12 символов). Создаётся и его кошелёк.
Существующий владелец повторно не создаётся. Без владельца начисление комиссии при
оплате завершится ошибкой и финансовая транзакция откатится.

Доступные свойства:

```properties
marketflow.payment-timeout-minutes=30
marketflow.return-window-days=7
marketflow.jobs.enabled=true
marketflow.jobs.delay-ms=60000
```

Фоновая задача обрабатывает каждый заказ в отдельной транзакции с блокировкой заказа.
Она отменяет просроченные неоплаченные заказы и освобождает ожидающие начисления.

## Проверка PostgreSQL

Обычный `./mvnw test` запускает unit-, MVC- и H2-тесты. PostgreSQL-проверки включаются
только при заданном `MARKETFLOW_TEST_POSTGRES_URL`. Используйте отдельную тестовую БД:
тесты создают уникальные схемы `migration_fresh_*`, `migration_upgrade_*`, `workflow_*`
и оставляют их для диагностики. Рабочие данные для проверки не нужны.

Пример PowerShell для отдельного PostgreSQL:

```powershell
$env:MARKETFLOW_TEST_POSTGRES_URL = 'jdbc:postgresql://127.0.0.1:55439/postgres'
$env:MARKETFLOW_TEST_POSTGRES_USER = 'marketflow_test'
# При необходимости задайте MARKETFLOW_TEST_POSTGRES_PASSWORD.
.\mvnw.cmd -B --no-transfer-progress clean verify
```

`MigrationPostgresTest` проверяет все миграции с нуля, повторный запуск и переход
V10 → V11 с подготовленными заказами, начислениями и продавцами.
`MarketplacePostgresTest` запускает настоящее приложение с `ddl-auto=validate`
и проверяет сохранение состояний вне общей тестовой транзакции: обработку заказа,
оплату, возврат, вывод, дедлайны, повторные запросы, откат при ошибке начисления,
разделение заказов по продавцам, страницы кабинетов, роли и CSRF.

V11 переносит начисления по старым открытым оплаченным заказам из доступного баланса
в ожидающий. Если старые балансы не покрывают такие начисления, ограничения БД
остановят миграцию. Перед применением на рабочей БД нужна её резервная копия;
успешная проверка на тестовых данных не проверяет содержимое рабочей базы.

# MarketFlow: идея текущей версии

MarketFlow — учебный backend многопродавцового маркетплейса. Проект показывает не набор несвязанных CRUD-экранов, а один связный сценарий:

```text
покупатель выбирает товары разных продавцов
→ создаёт и оплачивает один заказ
→ каждый продавец обрабатывает только свою часть
→ покупатель получает части
→ общий заказ завершается
```

## Роли

- `BUYER` работает с каталогом, корзиной, тестовыми картами и собственными заказами.
- `SELLER` также имеет возможности покупателя, управляет собственными товарами и выполняет доставку только своей части заказа.
- Существующие дополнительные роли не предоставляют отдельный бизнес-функционал в MVP.

## Основные правила

1. Один заказ может включать нескольких продавцов.
2. Название и цена товара сохраняются в `order_items` и не меняются вслед за каталогом.
3. Остаток списывается при успешной оплате, а не при создании заказа.
4. Карта, остатки, платёж и статусы изменяются в одной транзакции.
5. Повторный платёж защищён ключом идемпотентности.
6. Один продавец не видит и не изменяет часть другого.
7. Общий заказ завершается только после получения всех частей.
8. Неоплаченный заказ можно отменить; возвраты после оплаты не входят в MVP.
9. MVC и REST используют одну бизнес-логику.
10. RabbitMQ подключается только после стабилизации синхронного сценария.

## Граница учебной модели

Платёжные карты и баланс — внутренняя имитация. Проект не хранит реквизиты банковской карты и не переводит реальные деньги. Комиссии, выплаты, возвраты, модерация и аналитика сохранены только в полной резервной копии и архивной схеме старых данных.

# MarketFlow

[English version](README.md)

MarketFlow — учебный многопродавцовый маркетплейс на Java и Spring Boot. Текущая версия намеренно ограничена одним законченным сценарием:

```text
каталог → корзина → заказ → тестовая оплата → обработка продавцами → получение
```

Один заказ может содержать товары нескольких продавцов. Для каждого продавца создаётся отдельная часть заказа. Продавец видит и обрабатывает только свою часть, а общий заказ становится `COMPLETED` после получения всех частей.

## Что реализовано

Покупатель может зарегистрироваться, войти через HTTP-сессию, смотреть каталог, работать с корзиной, привязать тестовую карту, создать и оплатить заказ, посмотреть свои заказы и подтвердить получение каждой отправленной части.

Продавец регистрируется без отдельной заявки, управляет собственными товарами и остатками, видит только оплаченные части заказов со своими товарами и выполняет переходы:

```text
NEW → PROCESSING → SELLERSENDPRODUCT → USERGETPRODUCT
```

Общий заказ проходит состояния:

```text
CREATED → CONFIRMED → SELLERSSTARTWORK → SELLERSENDWORKANDSEND → COMPLETED
    └───────────────→ CANCELLED
```

Учебная оплата не связана с банком. Она атомарно проверяет владельца карты и баланс, списывает товарный остаток, уменьшает баланс тестовой карты, начисляет продавцам виртуальные средства за вычетом комиссии и начисляет комиссию платформе. До получения товара деньги находятся в `pendingBalance`, после получения переходят в `availableBalance`. Ключ идемпотентности и блокировки защищают от повторного списания и продажи последней единицы двум покупателям.

Доступны MVC + Thymeleaf страницы и REST API по OpenAPI-контрактам. Spring Security использует `JSESSIONID`, серверную сессию, роли `BUYER` / `SELLER` и CSRF-защиту.

## Что сознательно не входит в MVP

В рабочей версии нет заявок продавцов, модерации, аналитики, возвратов после получения товара и автоматического срока оплаты. Старые данные этих функций миграция V12 переносит в архивную PostgreSQL-схему `<основная_схема>_pre_mvp`, поэтому они не теряются. При этом доступны виртуальные кошельки, комиссия платформы, условный вывод на тестовую карту и возврат оплаченного заказа до начала его обработки продавцом.

## Стек

Java 21, Spring Boot 4, Spring MVC, Thymeleaf, Spring Security, Spring Data JPA, Hibernate, PostgreSQL, Flyway, OpenAPI, Maven, JUnit 5, Mockito и MockMvc.

## Основные таблицы

| Таблица | Назначение |
| --- | --- |
| `users`, `roles`, `user_roles` | Пользователи и роли |
| `products` | Товары, продавец, цена и остаток |
| `cart_items` | Корзины покупателей |
| `orders` | Общий заказ и его статусы |
| `order_items` | Снимки товара и цены на момент заказа |
| `seller_orders` | Независимые части заказа по продавцам |
| `payment_cards` | Тестовые карты и условный баланс |
| `wallet_accounts` | Ожидающие и доступные виртуальные балансы продавцов и платформы |
| `payment_transactions` | Оплата, начисления, комиссия, освобождение средств, вывод и возврат |
| `flyway_schema_history` | История миграций |

## Запуск

Создайте PostgreSQL-базу, скопируйте `.env.example` в `.env` и задайте подключение:

```env
DB_URL=jdbc:postgresql://localhost:5432/marketflow
DB_USERNAME=postgres
DB_PASSWORD=change_me
```

Запуск Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

Тесты:

```powershell
.\mvnw.cmd test
```

PostgreSQL-интеграционные тесты включаются переменными `MARKETFLOW_TEST_POSTGRES_URL`, `MARKETFLOW_TEST_POSTGRES_USER` и `MARKETFLOW_TEST_POSTGRES_PASSWORD`. Они создают уникальные схемы и не должны запускаться на рабочей базе.

## Основные страницы

| Путь | Назначение |
| --- | --- |
| `/register`, `/login` | Регистрация и вход |
| `/account/catalog` | Каталог |
| `/account/cart` | Корзина |
| `/account/orders` | Заказы покупателя |
| `/account/orders/{id}/payment` | Тестовая оплата |
| `/account/orders/{id}/workflow` | Части заказа и получение |
| `/seller/account` | Товары продавца |
| `/workspace/seller/orders` | Заказы продавца |

REST API находится под `/api/v1`; контракты — в каталоге [openapi](openapi).

Условный вывод доступных средств продавца: `POST /api/v1/wallet/withdraw`.

## Следующий этап

После стабилизации этого синхронного пути — RabbitMQ для асинхронных событий и уведомлений. Redis можно добавить позднее для кеширования каталога после появления измеримой пользы.
